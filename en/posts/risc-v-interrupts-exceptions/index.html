RISC-V Interrupt and Exception Mechanism

Analyzes the interrupt and exception mechanism of RISC-V, including privilege modes, exception and interrupt types, control and status registers, and the handling process.

Privilege Modes

RISC-V defines three privilege modes. Different combinations of these modes enable various system functionalities.

  • Machine Mode

    M-mode is the highest privilege level executable by a hardware thread (hart). It can access all resources and memory, supports system initialization and configuration (must be implemented), and is the only mode in most embedded systems.

  • User Mode

    Only allows execution of general-purpose instructions, not privileged ones. In U-mode, when an exception occurs, the system automatically jumps to M-mode to execute the exception handler. It can also trap into M-mode using the ecall instruction and return using the mret privileged instruction.

  • Supervisor Mode

    S-mode supports memory protection and is where the OS kernel runs. S-mode programs cannot use M-mode CSRs and privileged instructions but can use S-mode-specific ones like sret.

RISCV privilege mode bits: 00 → U-mode; 01 → S-mode; 11 → M-mode

M-mode exception handlers can forward exceptions to S-mode, but this reduces performance. Therefore, mideleg (Machine Interrupt Delegation) CSR is used to delegate certain interrupts to S-mode.

Lower privilege levels can be entered by configuring mstatus or sstatus and using mret, sret, and higher privilege levels can be entered via ecall.

Exception and Interrupt Types

Events that interrupt the normal execution of a program on RISC-V CPUs include exceptions and interrupts.

Exceptions

  • Faults:

    Detected between the start and completion of an instruction, e.g., illegal opcode during decoding, page fault on fetching or loading data, divide-by-zero error. These are unrecoverable and terminate the process.

  • Traps:

    Intentionally triggered via special instructions or control flags in a program. Upon meeting certain conditions, control transfers to a handler. After processing, execution resumes at the next instruction.

  • Termination:

    Caused by controller failure or memory errors. These are random and not tied to a specific instruction, leading to the termination of the faulty process.

Interrupts

While executing, the CPU may receive interrupt requests from peripherals or other sources. The CPU checks for interrupts after each instruction. If one is pending, it saves the next instruction address and jumps to the appropriate interrupt handler. Execution resumes after the handler completes.

  • External:

    Originating from off-core devices. Interrupt numbers in S-mode and M-mode are 9 and 11, respectively. The Platform-Level Interrupt Controller (PLIC) handles multiple sources and arbitrates priority.

  • Timer:

    In M-mode, the system defines two 64-bit memory-mapped registers, mtime and mtimecmp. When mtime exceeds mtimecmp, an M-mode timer interrupt (code 7) is triggered. In S-mode, the corresponding code is 5.

  • Software:

    Software interrupts in S-mode and M-mode are 1 and 3, respectively. Writing 1 to the memory-mapped msip register in M-mode triggers a software interrupt. Typically used for inter-hart communication.

  • Debug:

    Debug interrupt requests are sent from a remote host to the processor.

Control and Status Registers (CSRs)

CSRs are internal processor registers with 12-bit addresses. They are independent of memory and general-purpose register address spaces. In a 64-bit architecture, each is 8 bytes; in 32-bit, 4 bytes.

In 32-bit M-mode, the following CSRs are related to interrupts and exceptions:

  • mstatus

    M-mode status register with over 20 fields. MIE is the global interrupt enable bit. U and S modes use UIE, SIE. MPIE stores the previous interrupt enable state. MPP stores the privilege mode before the exception/interrupt.

  • mcause

    M-mode cause register with fields for Interrupt and Exception Code (CAUSE). The table below lists codes for various exceptions and interrupts.

  • mtvec

    M-mode trap-vector base address register with a 30-bit BASE and 2-bit MODE. MODE=00 jumps to BASE; MODE=01 jumps to BASE + CAUSE × 4.

  • mepc

    M-mode exception/interrupt return address. For traps, the handler must increment mepc to point to the next instruction to avoid re-execution.

  • mtval

    M-mode trap value register that stores auxiliary info related to the exception, such as the faulting address or instruction.

  • mie

    M-mode interrupt enable register. Fields MMIE, MTIE, and MSIE enable external, timer, and software interrupts respectively (requires mstatus.MIE to be 1).

  • mip

    M-mode interrupt pending register with fields MEIP, MTIP, and MSIP.

Handling Process

Hardware Response Phase

In M-mode, the response to an interrupt/exception includes:

  • Updating CSRs: mcause, mepc, and mtval
  • Updating relevant mstatus fields to store previous global interrupt state and privilege level (MIE, MPP), and disabling MIE
  • Setting PC to the address in mtvec and jumping to the handler

Software Handling Phase

M-mode exception/interrupt handlers perform:

  • Saving context/state
  • Using mcause to determine the cause and dispatch to the appropriate subroutine
  • Restoring context and returning via mret, which:
    • Sets mstatus.MIE = MPIE
    • Sets MPIE = 1
    • Sets privilege level = MPP
    • Sets MPP = 00
    • Loads PC = mepc to resume execution
