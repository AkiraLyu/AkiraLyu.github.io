Fixing Audio on the Huawei MateBook under Linux

Troubleshoot sound card detection and the internal microphone on a MateBook D 15 2022 running Arch Linux, extract DSP firmware from the Windows driver package, and configure the AVS driver.

Published August 27, 2026Last updated October 7, 2026

After installing Arch Linux on a Huawei MateBook D 15 2022, the sound card is not detected at all. Following earlier posts on the Arch Linux forums and setting the kernel module parameter snd_intel_dspcfg.dsp_driver to 1 restores the speakers and headphone jack, but the internal microphone still cannot record.

This happens because the internal digital microphone relies on the Intel audio DSP, which is disabled by the legacy HDA driver (dsp_driver=1). Meanwhile, the default SOF driver fails to load because an inaccurate entry in the board’s ACPI table causes it to match a nonexistent ES8336 codec. To get both audio playback and the internal microphone working without patching the kernel, we can extract the base DSP firmware from Huawei’s official Windows driver package and switch to the in-tree AVS (snd_soc_avs) driver.

Hardware Environment

Different batches of MateBooks may use different mainboard and sound card combinations. My hardware is listed below; if you encounter similar issues on the same series, you can use this as a reference:

ItemDetails
ModelMateBook D 15 2022 (BoDE-WFH9)
DMI Product / BoardBoDE-WXX9 / BoDE-WXX9-PCB-B3
Audio ControllerIntel Tiger Lake-LP, 8086:a0c8 (Subsystem 152d:1371)
HDA CodecConexant SN6140, 14f1:1f87

Root Cause Analysis

The dsp_driver parameter of the snd_intel_dspcfg module controls which Intel audio driver the kernel selects.

Default SOF Driver and the Faulty ACPI Entry

With automatic selection or dsp_driver=3, the kernel uses the SOF driver and fails during boot with a missing topology file error:

intel/sof-tplg/sof-tgl-es8336-dmic2ch.tplg

I also saw a similar prompt requesting the corresponding firmware when booting the LiveCD during a Debian installation.

The filename indicates that SOF selected the Everest ES8336 configuration and failed to register a sound card because the topology file is absent. Decompiling the ACPI DSDT reveals the following definition under \_SB.PC00.I2C2.ESSX:

Name (_HID, "ESSX8336")
Name (_CID, "ESSX8336")

Method (_STA, 0, NotSerialized)
{
    Return (0x0F)
}

Because _STA unconditionally returns 0x0F (reporting the device as present and functioning), SOF’s Tiger Lake matching table picks sof-essx8336. In reality, the machine has no corresponding I2C2 controller, the ESSX8336:00 node has neither a physical_node nor a bound driver, and the actual codec on the HDA bus is a Conexant SN6140.

During troubleshooting, I tested patching sound/soc/intel/common/soc-acpi-intel-tgl-match.c to return NULL in the ES8336 entry’s machine_quirk callback when DMI matched HUAWEI / BoDE-WXX9 / BoDE-WXX9-PCB-B3. Skipping that entry allowed SOF to fall back to the generic HDA configuration as expected.

HDA Driver and the Digital Microphone

Setting dsp_driver=1 forces the legacy HDA driver (snd_hda_intel). Inspecting /proc/asound/card*/codec#* confirms that the Conexant SN6140 codec is detected. Because the speakers, 3.5mm headphone jack, and analog headset microphone are wired to this chip, analog output and headset input work immediately.

However, the built-in microphone array is a digital microphone (DMIC) connected directly to the Intel DSP over PDM (dmesg shows DMICs detected in NHLT tables: 2). Because the legacy HDA driver does not enable the DSP, it cannot drive the internal DMIC, leaving only the 3.5mm analog microphone input available in desktop sound settings.

Firmware Extraction

Setting dsp_driver=4 selects the kernel’s AVS driver (snd_soc_avs), which supports both the HDA codec and the DSP digital microphone without recompiling the kernel. The linux-firmware-intel package already provides generic AVS topology files for HDA, DMIC, and HDMI, but lacks the base firmware for Tiger Lake:

/usr/lib/firmware/intel/avs/tgl/dsp_basefw.bin

This firmware can be extracted from the Windows driver package HUAWEI_Matebook_D_15_2022_ISST_10.29.0.6367.zip provided on Huawei’s official website (under Method 2, select the device model mentioned above, then click “View More” on the product page). Inside the package, IntcOED.inf matches controller A0C8 and subsystem SUBSYS_1371152D and specifies IntelSST/Fw/dsp_fw_release.bin as the base firmware.

The downloaded archive contains a nested ZIP file and two layers of NSIS .exe installers, which can be unpacked sequentially with 7z:

7z x HUAWEI_Matebook_D_15_2022_ISST_10.29.0.6367.zip
7z x HUAWEI_Matebook_D_15_2022_ISST_10.29.0.6367/HUAWEI_Matebook_D_15_2022_ISST_10.29.0.6367.zip
7z x ISST_10.29.0.6367.exe -olayer1
7z x layer1/ISST_10.29.0.6367.exe -opayload

The extracted payload/IntelSST/Fw/dsp_fw_release.bin has version 10.29.0.6313 (546,764 bytes), meeting the 10.29.0.5646 minimum version required for Tiger Lake in the kernel’s AVS driver. Install it to the firmware path:

sudo install -D -m 0644 payload/IntelSST/Fw/dsp_fw_release.bin \
    /usr/lib/firmware/intel/avs/tgl/dsp_basefw.bin

Configuring the AVS Driver

Edit /etc/modprobe.d/sound.conf and set dsp_driver to 4 (remove any dsp_driver=1 setting previously added in /etc/modprobe.d/ or the kernel boot parameters):

options snd_intel_dspcfg dsp_driver=4

On Arch Linux with mkinitcpio, regenerate the initramfs and reboot:

sudo mkinitcpio -P

After rebooting, cat /proc/asound/cards should list the audio devices registered by AVS:

 0 [PROBE   ]: AVS PROBE
 1 [HDAudio ]: AVS HD-Audio
 2 [DMIC    ]: AVS DMIC
 3 [HDMI    ]: AVS HDMI

The kernel log may briefly complain about a missing hda-14f11f87-tplg.bin before printing trying to load fallback topology hda-generic-tplg.bin; this fallback is expected.

Adjusting Microphone Gain

Even after the sound card is detected, the internal microphone volume may default to 0, resulting in silent recordings. Set the DMIC volume to 100% and save the ALSA state:

amixer -c DMIC set DMIC 100%
sudo alsactl store DMIC

Finally, select AVS HD-Audio as the output device and AVS DMIC as the input device in your desktop sound settings.
