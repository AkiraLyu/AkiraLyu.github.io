Running ros+gazebo+rviz with xwayland

Run ROS Noetic via Docker and display robot simulation GUI through XWayland under Arch Linux, including visualization support for Gazebo and RViz

In a Wayland environment, GUI applications cannot be displayed directly by mounting the X11 Unix socket and setting $DISPLAY. Instead, compatibility mechanisms provided by XWayland are needed. In addition, xhost must be used to authorize programs inside the container to access the host display service.

Download

Install XWayland-related tools:

sudo pacman -S xorg-xwayland xorg-xhost

For Debian-based systems: sudo apt install xwayland x11-xserver-utils

Pull the Docker image:

docker pull osrf/ros:noetic-desktop-full

Configuration

  • 1. Authorize access
xhost +si:localuser:root

This command allows the local user root (Docker containers usually run as root) to access the display server provided by XWayland.

If you want to revoke the authorization, run xhost -si:localuser:root after exiting the container.

  • 2. Start Docker

If not in the docker group:

usermod -aG docker $USER

Start the Docker daemon:

systemctl start docker

Create the container:

docker run -it \
  --env="DISPLAY=$DISPLAY" \
  --env="XDG_RUNTIME_DIR=$XDG_RUNTIME_DIR" \
  --env="ROS_HOSTNAME=127.0.0.1" \
  --env="ROS_MASTER_URI=http://127.0.0.1:11311" \
  --volume="$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY:$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY" \
  --volume="/tmp/.X11-unix:/tmp/.X11-unix" \
  --device=/dev/dri \
  --group-add video \
  --net=host \
  osrf/ros:noetic-desktop-full \
  bash

$DISPLAY: X11 compatible display address, usually :0
$XDG_RUNTIME_DIR: Path where the Wayland socket is located, usually /run/user/1000
$WAYLAND_DISPLAY: Wayland socket file name, generally wayland-0

Run source /opt/ros/noetic/setup.bash && roscore in the container, and run rviz in another terminal to verify the result.
