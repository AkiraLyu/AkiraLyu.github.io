修复 Linux 下华为 MateBook 的音频问题

排查 MateBook D 15 2022 在 Arch Linux 下的声卡识别与内置麦克风问题，从 Windows 驱动包提取 DSP 固件并配置 AVS 驱动。

发布 2026年8月27日最后修改 2026年10月7日

  • Linux
  • #Linux
  • #Arch Linux
  • #ALSA

华为 MateBook D 15 2022 安装 Arch Linux 后无法识别声卡。参考 Arch Linux 论坛的早期帖子将内核模块参数 snd_intel_dspcfg.dsp_driver 设为 1 后，可以让扬声器和耳机正常工作，但会导致内置麦克风无法录音。

造成这一现象的原因是内置数字麦克风需要通过 Intel 音频 DSP 工作，而 dsp_driver=1 所用的传统 HDA 驱动不启用 DSP；默认启用的 SOF 驱动又因主板 ACPI 表信息有误，匹配了不存在的 ES8336 编解码器而加载失败。要同时恢复播放与内置麦克风录音，可以通过从华为官方的 Windows 驱动包中提取 DSP 基础固件，并改用内核自带的 AVS（snd_soc_avs）驱动来实现。

硬件环境

不同批次的 MateBook 可能采用不同的主板与声卡组合，本人使用如下硬件，同系列如果碰到类似问题可以适当参考：

项目信息
型号MateBook D 15 2022（BoDE-WFH9）
DMI 产品名 / 主板BoDE-WXX9 / BoDE-WXX9-PCB-B3
音频控制器Intel Tiger Lake-LP，8086:a0c8（子系统 152d:1371）
HDA 编解码器Conexant SN6140，14f1:1f87

问题分析

snd_intel_dspcfg 模块的 dsp_driver 参数决定了内核使用的 Intel 音频驱动。

默认 SOF 驱动与 ACPI 表错误

在自动选择或设置 dsp_driver=3 时，内核默认使用 SOF 驱动，并在启动日志中报错找不到拓扑文件：

intel/sof-tplg/sof-tgl-es8336-dmic2ch.tplg

在安装 Debian 启动 LiveCD 时也可能出现类似提示，要求加载对应的固件。

文件名表明 SOF 选择了 Everest ES8336 方案，因缺少该拓扑文件而未能注册声卡。反编译 ACPI 的 DSDT 表可以看到，设备 \_SB.PC00.I2C2.ESSX 的定义如下：

Name (_HID, "ESSX8336")
Name (_CID, "ESSX8336")

Method (_STA, 0, NotSerialized)
{
    Return (0x0F)
}

_STA 硬编码返回 0x0F（设备存在且正常工作），导致 SOF 的 Tiger Lake 匹配表优先匹配了 sof-essx8336。但实际上系统中并不存在对应的 I2C2 控制器，ESSX8336:00 节点下既没有 physical_node 也未绑定任何驱动，机身真实搭载的是 HDA 总线上的 Conexant SN6140。

排查过程中曾尝试修改内核部分源码 sound/soc/intel/common/soc-acpi-intel-tgl-match.c，在 ES8336 匹配项的 machine_quirk 回调中针对 HUAWEI / BoDE-WXX9 / BoDE-WXX9-PCB-B3 返回 NULL 以跳过该条目，修改后 SOF 即可正常回退到通用 HDA 配置。

HDA 驱动与数字麦克风

设置 dsp_driver=1 会强制使用传统 HDA 驱动（snd_hda_intel），此时查看 /proc/asound/card*/codec#* 可以直接识别出 Conexant SN6140。扬声器、3.5mm 耳机孔和耳麦模拟麦克风均挂在该芯片下，因此外放与耳机孔都能立即工作。

然而机身自带的阵列麦克风是数字麦克风（DMIC），通过 PDM 接口直接连在 Intel DSP 上（dmesg 中可见 DMICs detected in NHLT tables: 2）。HDA 驱动不启用 DSP，无法驱动内置数字麦克风，此时桌面音频设置中的麦克风仅对应 3.5mm 接口的模拟输入。

提取固件

设置 dsp_driver=4 可启用内核的 AVS 驱动（snd_soc_avs），同时驱动 HDA 编解码器与 DSP 数字麦克风，无需重新编译内核。linux-firmware-intel 包已经提供了 HDA、DMIC 和 HDMI 的通用 AVS 拓扑文件，但会缺少 Tiger Lake 平台的基础固件：

/usr/lib/firmware/intel/avs/tgl/dsp_basefw.bin

该固件可以从华为官网提供的 Windows驱动包 HUAWEI_Matebook_D_15_2022_ISST_10.29.0.6367.zip 中提取（在方法二中选择开头提到的设备型号，进入对应页面后选择查看更多）。驱动包的 IntcOED.inf 中包含本机控制器 A0C8 与子系统 SUBSYS_1371152D，指向的基础固件为 IntelSST/Fw/dsp_fw_release.bin。

下载驱动压缩包后，里面包含一层嵌套的 ZIP 和两层 NSIS .exe 安装包，可直接用 7z 逐层解压：

7z x HUAWEI_Matebook_D_15_2022_ISST_10.29.0.6367.zip
7z x HUAWEI_Matebook_D_15_2022_ISST_10.29.0.6367/HUAWEI_Matebook_D_15_2022_ISST_10.29.0.6367.zip
7z x ISST_10.29.0.6367.exe -olayer1
7z x layer1/ISST_10.29.0.6367.exe -opayload

提取出的 payload/IntelSST/Fw/dsp_fw_release.bin 版本为 10.29.0.6313（546764 字节），满足内核 AVS 驱动对 Tiger Lake 平台要求的最低版本 10.29.0.5646。将其安装到目标路径：

sudo install -D -m 0644 payload/IntelSST/Fw/dsp_fw_release.bin \
    /usr/lib/firmware/intel/avs/tgl/dsp_basefw.bin

配置 AVS 驱动

编辑 /etc/modprobe.d/sound.conf，将 dsp_driver 设为 4（移除此前在 /etc/modprobe.d/ 或内核启动参数中设置过 dsp_driver=1）：

options snd_intel_dspcfg dsp_driver=4

对于使用 mkinitcpio 的 Arch Linux，重新生成 initramfs 后重启：

sudo mkinitcpio -P

重启后查看 cat /proc/asound/cards，应该能看到 AVS 注册的各个音频设备：

 0 [PROBE   ]: AVS PROBE
 1 [HDAudio ]: AVS HD-Audio
 2 [DMIC    ]: AVS DMIC
 3 [HDMI    ]: AVS HDMI

内核日志中可能会先提示缺少 hda-14f11f87-tplg.bin，随后输出 trying to load fallback topology hda-generic-tplg.bin，属正常回退行为。

调整麦克风增益

声卡识别成功后，内置麦克风的默认音量可能为 0，导致录音没有声音。将 DMIC 音量调至 100% 并保存 ALSA 状态：

amixer -c DMIC set DMIC 100%
sudo alsactl store DMIC

随后在桌面声音设置中将输出设备选为 AVS HD-Audio、输入设备选为 AVS DMIC，播放和内置麦克风录音即恢复正常。
